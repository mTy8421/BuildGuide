คู่มือการติดตั้งและใช้งาน
(Android Setup & Build Guide)

เอกสารนี้รวบรวมขั้นตอนการเตรียมสภาพแวดล้อม (Environment Setup), การรันโปรเจกต์ในโหมด Development, และขั้นตอนการ Build ไฟล์ติดตั้ง APK ผ่าน Gradle (gradlew) สำหรับโปรเจกต์ AccountMobile

1. ความต้องการของระบบ (Prerequisites)

ซอฟต์แวร์ / เครื่องมือ เวอร์ชันที่แนะนำ หมายเหตุ
Node.js v20.x หรือ v22.x (LTS) ตรวจสอบด้วย node -v
Java Development Kit (JDK) OpenJDK 17 LTS สำคัญมาก: Android Gradle Plugin (AGP) ไม่รองรับ JDK 25/27
Android Studio เวอร์ชันล่าสุด (Ladybug หรือใหม่กว่า) สำหรับจัดการ Android SDK, NDK และ Emulator
Android SDK Platform API 35 / 36 ติดตั้งผ่าน SDK Manager ใน Android Studio
Android SDK Build-Tools 35.0.0 หรือ 36.0.0 ติดตั้งผ่าน SDK Manager
Android NDK & CMake NDK 27.x ขึ้นไป, CMake 3.22+ จำเป็นสำหรับการคอมไพล์ C++ Native Modules

วิธีติดตั้ง JDK 17 (หากยังไม่มี)

สามารถติดตั้งผ่าน Windows Package Manager (winget) ได้ด้วยคำสั่ง:

powershell 
winget install --id Microsoft.OpenJDK.17 --silent --accept-package-agreements --accept-source-agreements

พาธเริ่มต้นจะอยู่ที่:

path 
C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot

2. การตั้งค่า Environment Variables

เพิ่มตัวแปรระบบ (System/User Environment Variables) บน Windows เพื่อให้คำสั่งต่าง ๆ ทำงานได้ถูกต้อง:

2.1 JAVA_HOME

กำหนดให้ชี้ไปยังโฟลเดอร์ JDK 17:

  • ตัวแปร: JAVA_HOME
  • ค่า (Path): C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot

ตั้งค่าผ่าน PowerShell (รันครั้งเดียว):

powershell 
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot", "User")

2.2 ANDROID_HOME

กำหนดให้ชี้ไปยังโฟลเดอร์ Android SDK:

  • ตัวแปร: ANDROID_HOME
  • ค่า (Path): C:\Users\<ชื่อผู้ใช้>\AppData\Local\Android\Sdk

ตั้งค่าผ่าน PowerShell (แทนที่ <Username> ด้วยชื่อผู้ใช้ของคุณ):

powershell 
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "$env:LOCALAPPDATA\Android\Sdk", "User")

2.3 PATH

เพิ่มพาธเครื่องมือ Android ลงในตัวแปร Path:

  • %ANDROID_HOME%\platform-tools (สำหรับใช้งานคำสั่ง adb)
  • %ANDROID_HOME%\cmdline-tools\latest\bin
  • %JAVA_HOME%\bin

3. การตั้งค่าไฟล์ Config สำหรับ Android

3.1 ไฟล์ android/local.properties

ไฟล์นี้ใช้ระบุตำแหน่งของ Android SDK ในเครื่อง ให้สร้างไฟล์ android/local.properties (หากยังไม่มี) และระบุ:

properties 
sdk.dir=C\:\\Users\\<ชื่อผู้ใช้>\\AppData\\Local\\Android\\Sdk

(ตัวอย่างเครื่องปัจจุบัน: sdk.dir=C\:\\Users\\mighty\\AppData\\Local\\Android\\Sdk)

3.2 ไฟล์ android/gradle.properties

ตรวจสอบให้แน่ใจว่าได้ระบุ org.gradle.java.home ชี้ไปที่ JDK 17 เพื่อป้องกันไม่ให้ Gradle สลับไปใช้ JDK ตัวอื่น:

properties 
org.gradle.jvmargs=-Xmx2048m -XX:MaxMetaspaceSize=512m
org.gradle.java.home=C\:/Program Files/Microsoft/jdk-17.0.20.101-hotspot

4. การติดตั้ง Dependencies

เปิด Terminal ที่ root โฟลเดอร์ของโปรเจกต์ (D:\accountMobile):

bash 
# ติดตั้งแพ็กเกจ npm ทั้งหมด
npm install
ข้อควรระวังสำหรับ Expo

หากต้องการติดตั้งไลบรารีใหม่ที่เป็นของ Expo แนะนำให้ใช้คำสั่ง npx expo install <package-name> เสมอ เพื่อให้ได้เวอร์ชันที่ตรงกับ Expo SDK 57

5. การรันแอปพลิเคชัน (Development Mode)

5.1 เริ่มต้นรัน Metro Dev Server

bash 
npm start
# หรือ
npx expo start

5.2 รันแอปพลิเคชันบน Android (Emulator หรือ เครื่องจริง)

ตรวจสอบว่าเปิด Emulator หรือเสียบสาย USB (เปิด USB Debugging) แล้ว ตรวจสอบด้วยคำสั่ง:

bash 
adb devices

จากนั้นรันคำสั่ง:

bash 
npm run android
# หรือ
npx expo run:android

คำสั่งนี้จะทำการ build ดีบัก APK และติดตั้งลงอุปกรณ์ พร้อมเปิด Metro Bundler เพื่อรองรับ Fast Refresh

6. การ Build ไฟล์ APK ด้วย Gradle (gradlew)

ความแตกต่างระหว่าง Debug APK และ Release APK

📦 Release APK

มีการรวบรวมโค้ด JavaScript ทั้งหมด แปลงเป็น Hermes Bytecode ฝัง Assets และ Resource ลงในตัว APK ทำให้เป็นไฟล์แบบ Standalone สามารถส่งไฟล์ไปติดตั้งและเปิดใช้งานได้ทันทีบนอุปกรณ์ใดก็ได้โดยไม่ต้องเปิดเซิร์ฟเวอร์

🛠️ Debug APK

ตัว APK จะรอการเชื่อมต่อกับ Metro Development Server เหมาะสำหรับใช้ระหว่างขั้นตอนการพัฒนาและทดสอบดีบัก

6.1 ขั้นตอนการ Build Release APK (แนะนำสำหรับนำไปใช้งาน)

  1. เปิด PowerShell หรือ Command Prompt
  2. ไปยังโฟลเดอร์ android:
    powershell 
    cd D:\accountMobile\android
  3. สั่งหยุด daemon เก่า (ถ้ามี) และเริ่ม Build Release APK:
    powershell 
    .\gradlew.bat assembleRelease

    (หากต้องการ Clean Build ก่อน ให้รัน .\gradlew.bat clean assembleRelease)

  4. ตำแหน่งไฟล์ APK ที่ได้:
    path 
    D:\accountMobile\android\app\build\outputs\apk\release\app-release.apk

6.2 ขั้นตอนการ Build Debug APK

หากต้องการสร้าง APK สำหรับการทดสอบดีบัก:

powershell 
cd D:\accountMobile\android
.\gradlew.bat assembleDebug

ตำแหน่งไฟล์ APK ที่ได้:

path 
D:\accountMobile\android\app\build\outputs\apk\debug\app-debug.apk

6.3 วิธีติดตั้ง APK ลงในมือถือผ่าน ADB

เมื่อเสียบสาย USB และเปิด USB Debugging แล้ว สามารถใช้คำสั่งนี้เพื่อติดตั้ง APK ลงเครื่องได้โดยตรง:

powershell 
adb install -r D:\accountMobile\android\app\build\outputs\apk\release\app-release.apk

(ตัวเลือก -r หมายถึง reinstall เพื่ออัปเดตทับแอปเดิมโดยไม่ลบข้อมูล)

7. การตรวจสอบคุณภาพโค้ด (Lint & Typecheck)

ก่อนทำการ build หรือ commit โค้ด ควรตรวจสอบความถูกต้องเสมอ:

bash 
# ตรวจสอบ TypeScript Types
npx tsc --noEmit

# ตรวจสอบโค้ดด้วย ESLint (Expo Lint)
npx expo lint

8. การแก้ไขปัญหาที่พบบ่อย (Troubleshooting)

1. Error: Error while executing process ... jlink.exe with arguments หรือ JdkImageTransform ล้มเหลว
สาเหตุ: เกิดจากการใช้ Java เวอร์ชันที่ใหม่เกินไป (เช่น JDK 25 หรือ JDK 27) ซึ่งระบบโมดูลไม่เข้ากันกับ Android Gradle Plugin
วิธีแก้: ติดตั้ง JDK 17 LTS และกำหนด org.gradle.java.home=C\:/Program Files/Microsoft/jdk-17.0.20.101-hotspot ในไฟล์ android/gradle.properties
2. Error: SDK location not found. Define a location with an ANDROID_HOME...
สาเหตุ: Gradle หาตำแหน่งของ Android SDK ไม่พบ
วิธีแก้: สร้างไฟล์ android/local.properties และระบุ sdk.dir=C\:\\Users\\<Username>\\AppData\\Local\\Android\\Sdk
3. Gradle Daemon เกิดอาการค้างหรือกินหน่วยความจำสูง
วิธีแก้: สั่งปิดการทำงานของ Daemon ทั้งหมดด้วยคำสั่ง:
powershell 
cd android
.\gradlew.bat --stop
4. มีการติดตั้งไลบรารีที่มี Native Code เพิ่มเติม แล้ว Build ไม่ผ่าน
วิธีแก้: สำหรับโปรเจกต์ Expo ที่ใช้ Prebuild หากมีการเพิ่มหรือเปลี่ยน Native Library ให้รันคำสั่ง:
bash 
npx expo prebuild --clean
เพื่อสร้างโฟลเดอร์ android/ ใหม่ให้สอดคล้องกับการตั้งค่าล่าสุดใน app.json และ package.json
